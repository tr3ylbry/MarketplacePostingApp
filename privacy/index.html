MarketplacePostingApp

Development Privacy Notice

Last updated November 5, 2026.

Scope and current operation

MarketplacePostingApp is a development project for organizing items, storing private listing photos, previewing marketplace formats and explicitly managing Reverb drafts. The application currently runs locally, with local PostgreSQL storage and external authentication, image-storage and marketplace services. Development testing uses GitHub authentication, a development Vercel Private Blob store and Reverb Sandbox. A local-only eBay Sandbox OAuth seller-connection flow is implemented, but real eBay OAuth and two-seller identity acceptance testing is still pending separate owner approval. It is not a publicly deployed application.

Information used and why

  • Sign-in and sessions: GitHub account identifiers, name, email and avatar information identify the user and support owner-authorized access. Better Auth stores provider account records, encrypted OAuth tokens where applicable, and database-backed sessions. Session records may include IP address and browser information.
  • Items and photos: entered titles, descriptions, prices, item attributes, marketplace preferences and publication history support inventory and draft workflows. Image bytes and metadata, including original filenames, file types, size and order, support uploads and private viewing. Image checks do not guarantee removal of embedded metadata; avoid uploading personal or location-sensitive photos for testing.
  • Reverb connections and actions: an encrypted Personal Access Token, shop identity, environment and connection timestamps support explicit provider requests. Draft reviews, attempt records and remote listing IDs/status help reconcile actions and avoid unsafe duplicate requests.
  • eBay Sandbox connections: when explicitly authorized, the connection flow processes an authorization code on the server and stores encrypted access/refresh tokens, granted permissions, expiry times, a hashed stable seller identifier and a seller username label. Hashed one-use authorization state and session/configuration bindings protect the callback. Authorization codes and raw seller profiles are not retained as application records; limited state validity does not guarantee immediate deletion of expired records.

Storage and third-party services

PostgreSQL holds application records; Vercel Private Blob holds uploaded image bytes. GitHub handles authentication. Explicit Reverb draft creation sends selected listing content and temporary private photo access to Reverb, which can retain its own copies. Ordinary local saves and page navigation do not automatically push listing content to Reverb. Explicit eBay Sandbox connection actions use eBay for seller consent and server-side token exchange, authenticated identity checks and token renewal; the current eBay flow sends no inventory, offers or photos.

These providers process information involved in their services under their own policies. This notice describes the application, not a guarantee about provider retention or operations. This public notice is a static GitHub Pages page, separate from the application and database. It contains no analytics scripts, tracking pixels, forms or application authentication. GitHub Pages records visitor IP addresses for security purposes, as described in GitHub's hosting documentation.

eBay Sandbox connection and deferred features

The implemented local-development flow uses Sandbox authorization-code OAuth and read-only authenticated Trading GetUser identity checks. It does not use a browser-entered seller ID or treat mocked Commerce Identity responses as seller proof. Real callback delivery, distinct stable identities for two Sandbox sellers, token refresh and disconnection behavior have not yet completed real-provider acceptance testing. Merely opening the connection page does not contact eBay.

eBay inventory-item creation, media/photo export, business-policy and location creation, offers, listing publication and synchronization are not implemented in this stage. These remain separately approved future work, not current functionality or permission to make provider writes. Production sellers and public application deployment are not included. Review this notice again before adding those data flows.

Security and browser data

The server checks authenticated ownership before accessing listings, connections or images. Reverb credentials and the eBay connection flow's access/refresh tokens are encrypted server-side under separate keys; GitHub OAuth token encryption is configured through Better Auth. This does not mean every database field is encrypted, and encryption cannot protect data if the running server or its keys are compromised.

Session cookies are HttpOnly and SameSite=Lax; Secure cookies are used on HTTPS origins. The eBay connection workflow requires trusted HTTPS on loopback. Other local-development workflows may use HTTP only on loopback with matching authentication configuration. Provider credentials and signed photo URLs are not persisted in browser localStorage/sessionStorage or intentionally written to application logs. Temporary image URLs are bearer access: anyone receiving a valid URL can use it until expiry, and downloaded copies cannot be recalled.

Older local listings may remain in browser storage. Import is an explicit action and does not delete that original browser data. PostgreSQL is the source of truth for normal current use.

Disconnection and deletion

Signing out ends the current application session; it does not erase account or listing records or revoke provider authorization. Reverb disconnection removes the local stored connection, not the provider's token or remote drafts, and cannot cancel a request already in flight. GitHub and Reverb authorizations can be managed or revoked through those providers. eBay disconnection clears locally stored OAuth tokens and pending authorization state while retaining a minimal versioned connection record to reject stale in-flight results; it does not revoke eBay consent or erase eBay-held data. Manage or revoke eBay authorization separately through eBay.

Deleting a local listing removes its application records and queues photo cleanup. It does not automatically delete a remote Reverb draft. Remote draft deletion is a separate explicit action; it leaves the local item and photos intact. Removing a local photo does not erase copies already downloaded by a provider or recipient.

Retention and limits

There is no fixed automatic account-data deletion schedule or complete self-service account-erasure interface. Development records remain until removed or cleaned up. Privacy/deletion requests require review by the project maintainer; deletion timing and scope depend on the records, service and available controls. No immediate or complete erasure guarantee is made.

Removing an image or listing hides it from the application immediately, but physical image deletion may be delayed. Photos shared for Reverb ingestion remain protected for at least the issued 15-minute capability lifetime plus a one-minute safety margin. A durable cleanup ledger and operator-run cleanup handle deferred objects and retries; physical deletion may occur later if cleanup has not run or a provider operation fails. Local deletion does not establish deletion from independent provider copies or any separately maintained backups.
